# 프로젝트 역할 분담

## 원칙

역할은 사람 수가 아니라 책임의 분리를 뜻한다. 한 사람이 여러 역할을 맡을 수 있지만,
각 태스크에는 담당자와 검토자가 있어야 한다. AI 에이전트는 실행자이며 최종 승인자가
아니다.

## 역할

| 역할 | 책임 | 산출물 | 최종 권한 |
|---|---|---|---|
| Product Owner | 문제·사용자·범위·성공기준 결정 | PRD, 우선순위, 범위 제외 | 제품 범위 승인 |
| Spec/Planner | 요구사항을 테스트 가능한 명세와 계획으로 변환 | SPEC, PLAN, 데이터 모델, 계약 | 설계안 제안 |
| UX/Frontend | 사용자 흐름·접근성·표현 구현 | HTML, CSS, 브라우저 상태 | UI 구현 |
| Automation/AI | n8n 흐름·프롬프트·분류 계약 구현 | workflow JSON, 정책 버전, adapter | 구현 제안 |
| QA/Evaluator | 정상·경계·실패·안전·개인정보 검증 | fixture, 평가 결과, 회귀 기록 | 통과/실패 판정 제안 |
| Security/Safety Reviewer | 악용·개인정보·오탐·복구 경로 검토 | 보안 체크리스트, 위험 수용 여부 | 출시 보류 요청 |
| Human Approver | AI 변경과 외부 영향 최종 판단 | 승인, 반려, 예외 결정 | 파일 변경·커밋·배포 승인 |

## 한 태스크의 기본 인계

`Product Owner → Spec/Planner → Implementer(AI 또는 사람) → QA/Evaluator → Human Approver`

안전·개인정보·인증·외부 전송이 포함된 작업은 `Security/Safety Reviewer`를 반드시 거친다.

## 현재 프로젝트 기본 배정

- 제품·범위: 사용자와 `team_prd.md`
- 명세·계획: Codex + 사용자의 검토
- 구현: Codex
- 검증: Codex가 실행하고 사용자가 결과를 검토
- 최종 승인·커밋·배포: 사용자

## 결정권 경계

- AI는 파일 삭제, 비가역 외부 요청, 커밋, push, 배포를 독자적으로 확정하지 않는다.
- AI는 안전 판단을 보조할 수 있지만, 불확실한 사용자를 자동 차단하는 유일한 근거가
  되지 않는다.
- 사람은 AI 결과를 그대로 승인하지 않고 명세·테스트·diff를 함께 확인한다.
