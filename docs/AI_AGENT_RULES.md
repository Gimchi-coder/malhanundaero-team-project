# AI Agent 운영 규칙

## 1. 기본 행동

1. 요청을 `Goal`, `User`, `Behavior`, `Constraints`, `Success`로 해석한다.
2. 관련 `AGENTS.md`, PRD, SPEC, PLAN, TASKS를 먼저 읽는다.
3. 한 번에 하나의 태스크만 `IN PROGRESS`로 둔다.
4. 모호한 요구는 임의로 넓히지 않고, 안전한 기본값과 가정을 기록한다.
5. 변경 전 대상 파일·영향 범위·검증 방법을 사용자에게 설명한다.
6. 변경 후 diff, 문법, 관련 테스트를 확인하고 결과를 보고한다.

## 2. 하지 말아야 할 행동

- 비밀번호, API 키, 토큰, 실명, 이메일을 코드·로그·문서에 기록하지 않는다.
- 브라우저에서 외부 AI 제공자에게 직접 비밀 키를 전송하지 않는다.
- 사용자의 승인 없이 파일을 만들거나 수정·삭제하지 않는다.
- 사용자가 요청하지 않은 라이브러리 설치, 커밋, branch, push, merge, 배포를 하지 않는다.
- 기존 사용자 변경사항을 reset, checkout, 강제 삭제로 되돌리지 않는다.
- 테스트가 없는 상태에서 “완료”라고 보고하지 않는다.
- AI 안전 분류 결과만으로 불확실한 사용자를 영구 차단하지 않는다.

## 3. 구현 규칙

- 입력과 출력은 명확한 JSON 또는 함수 계약으로 정의한다.
- 함수는 한 가지 책임만 갖도록 분리한다.
- 사용자 입력은 `textContent`, 검증된 DOM API 등 안전한 방식으로 렌더링한다.
- 비동기 작업은 로딩·성공·실패·재시도·보류·수동검토 상태를 제공한다.
- 외부 서비스 실패 시 안전 기능은 fail-closed로 동작한다.
- AI 응답은 스키마를 검증하고, 누락·충돌·낮은 신뢰도 결과는 승인하지 않는다.
- 로그에는 원문 개인정보 대신 request ID, 결과, 지연, 재시도 횟수만 남긴다.

## 4. 동네 광장 AI 규칙

### 추천 AI

- 활동의 목적·시간·장소·인원과 사용자가 직접 입력한 관심사·편안함만 사용한다.
- 사람을 사람에게 매칭하지 않고 활동을 추천한다.
- 추천 이유를 평범한 문장으로 설명한다.
- 근거 없는 성격·감정·민감정보 추론을 하지 않는다.
- 추천이 없으면 억지 결과 대신 질문 또는 빈 상태를 보여준다.

### 안전검토 AI

- 키워드뿐 아니라 문맥·의도·행동 요청을 분석한다.
- 연애·성비·헌팅, 괴롭힘, 사기·송금, 판매·투자, 포교, 무관한 모집을 검사한다.
- 띄어쓰기·기호·은어·완곡 표현·우회 표현을 평가셋에 포함한다.
- 결과는 `approved`, `held`, `manual_review`, `unavailable` 중 하나여야 한다.
- `low confidence`, malformed response, timeout, provider failure는 승인하지 않는다.
- 보류 사유는 비난하지 않는 언어로 설명하고 수정·재시도·운영자 검토 경로를 제공한다.
- 100% 탐지를 주장하지 않고 오탐·누락을 측정한다.

## 5. 도구·MCP·n8n 규칙

- 로컬 함수는 결정적 계산·검증에 사용한다.
- 외부 데이터·공유 시스템은 MCP 또는 보호된 n8n/server boundary를 사용한다.
- 도구 설명과 입력 스키마는 좁고 명확하게 작성한다.
- 읽기 도구와 쓰기 도구를 구분한다.
- 삭제·전송·게시 같은 위험 동작은 사람 승인 게이트를 둔다.
- n8n workflow는 입력 검증 → 최소화 → 처리 → 분기 → 응답 계약 순서를 지킨다.

## 6. AI 응답 보고 형식

모든 작업 완료 보고는 다음을 포함한다.

- 변경 파일
- 핵심 변경 내용
- 실행한 검증과 결과
- 남은 위험·제한사항
- 사용자가 검토하거나 승인할 항목
